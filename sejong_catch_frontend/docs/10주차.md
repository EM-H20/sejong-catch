## **특이사항**

10주차는 백엔드 Swagger 문서가 지속 지연되어, Feed 페이지를 집중적으로 리팩토링하는 작업에 몰두했습니다.

**주요 성과:**

1. **대규모 컴포넌트 분리**: 534줄의 거대한 feed_page.dart를 214줄로 60% 감소시키고, 3개의 재사용 가능한 컴포넌트(feed_card, feed_card_thumbnail, feed_category_filter)로 분리하여 가독성과 유지보수성을 극대화했습니다.

2. **타이포그래피 시스템 구축**: AppTextStyles를 신규 생성하여 17개의 표준화된 텍스트 스타일을 정의했습니다. 이제 프로젝트 전체에서 fontSize 하드코딩 없이 일관된 타이포그래피를 사용할 수 있습니다.

3. **디자인 토큰 확장**: AppColors에 투명도 색상 토큰 2개, AppSpacing에 Feed 전용 토큰 7개를 추가하여 디자인 시스템 일관성을 더욱 강화했습니다.

4. **Overflow 에러 완전 해결**: SliverAppBar에서 발생하던 "BOTTOM OVERFLOWED BY 1.0 PIXELS" 에러를 근본 원인부터 분석하여 완전히 해결했습니다. feed_category_filter.dart의 하드코딩된 높이와 SliverAppBar의 복잡한 레이아웃이 충돌하는 문제였으며, 기본 AppBar로 전환하여 단순화했습니다.

**기술 부채 감소:**
- 하드코딩 제거: 20+ 곳
- 새로운 디자인 토큰: 26개 (AppTextStyles 17개 + AppColors 2개 + AppSpacing 7개)
- 코드 감소율: 60% (feed_page.dart)
- Flutter Analyze: 에러/경고 0건 유지

이제 Swagger 문서만 나오면 바로 실제 API 연동에 들어갈 수 있는 완벽한 상태이며, 다른 페이지(검색/줄서기/프로필)도 같은 방식으로 리팩토링할 준비가 되었습니다.
